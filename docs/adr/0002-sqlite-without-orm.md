# 0002. Хранение: SQLite без ORM

## Контекст

Нужна локальная база для тем, фраз и истории показов; десятки тысяч строк, работа без интернета. Выбран SQLite; схема — три таблицы.

## Решение

Фразы, темы и события показа хранятся в одном файле SQLite, доступ — через `Microsoft.Data.Sqlite` напрямую. Схема создаётся и мигрирует по `PRAGMA user_version`. Настройки лежат отдельно, в `settings.json`.

## Почему

Отвергнут **EF Core**: для трёх таблиц он добавляет более 10 МБ и время старта, а утилита должна быть лёгкой.

## Последствия

- SQL пишется вручную; каждое изменение схемы — вручную написанная миграция с повышением `user_version`.
- Соединения открываются без пула, чтобы файл освобождался сразу после закрытия: это нужно для резервной копии, восстановления и переименования повреждённой базы. Утечка открытого соединения ломает эти операции.
- Восстановление из копии обязано закрыть все соединения и пересоздать репозиторий; прямой вызов сервиса резервных копий в обход контроллера приложения даёт рассинхрон.
- Время хранится строкой в UTC; «сегодня» в статистике считается по локальной дате.
- Удаление темы или фразы каскадно удаляет их историю — вернуть её нельзя.
