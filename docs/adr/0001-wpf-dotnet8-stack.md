# 0001. Стек: C# + WPF на .NET 8

## Контекст

Нужна фоновая утилита для Windows: окно поверх всех без фокуса, прозрачность, трей, автозапуск, глобальные горячие клавиши, малый расход памяти и установка копированием одного файла. Сравнивались пять стеков.

## Решение

Программа пишется на C# + WPF (.NET 8). Логика вынесена в библиотеку без ссылок на UI, окна и трей — в приложении WPF. Трей — штатный `NotifyIcon` из WinForms. Распространяется как один self-contained `WinDeutsch.exe`.

## Почему

Всё, из чего состоит продукт, в WPF делается штатными средствами и парой вызовов Win32. Отвергнуто:

- **WinUI 3** — прозрачность окна ограничена и требует Win32 interop; нет трея без сторонних пакетов; упаковка через MSIX сложнее, а автозапуск для MSIX устроен иначе.
- **Tauri** — две кодовые базы (Rust + JS), нужны Rust и MSVC, прозрачность через WebView2 с оговорками.
- **Electron** — 150–250 МБ в простое против 50–80 у WPF и большой дистрибутив: тяжело для утилиты, которая должна быть незаметной.
- **Python + PySide6** — упаковка PyInstaller и медленный старт, слабее для нативного Windows-UX; поддержка PySide6 под установленным Python 3.14 не подтверждена.

## Последствия

- Только Windows 10/11 x64; перенос на другую ОС означает переписывание окон.
- Self-contained single-file exe весит около 164 МБ (замер при сборке каркаса). «Один маленький файл» не получился, хотя ставить .NET не нужно.
- Рабочий набор в Debug-сборке замерен около 139 МБ при ориентире «до 100 МБ»; ориентир не подтверждён, нужна проверка Release-публикации.
- WinForms подключён только ради `NotifyIcon`; из-за этого в приложении убраны неявные импорты `System.Windows.Forms` и `System.Drawing`, чтобы имена не сталкивались с WPF.
- UI-слой тестами не покрывается; проверяется только запуском.
